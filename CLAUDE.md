# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Call Harbison (callharbison.com): marketing site + lead intake for Nathanael Harbison, a licensed Kern County, CA REALTOR® who buys houses directly or lists them. Static pages generated by Node, plus Vercel serverless functions. See README.md for deployment, env vars, the shared HQ CRM and the Neon/Supabase setup.

## Commands

```bash
npm ci                     # Node 22 (CI uses 22). PGlite is a dev dependency used by the SQL tests.
npm run dev                # build once, then serve http://localhost:3000 with the APIs
npm run dev -- --mock      # same, with synthetic HQ data; HQ login password "demo"
npm run build              # writes ./dist (English + /es Spanish), sitemap, robots, llms.txt
npm start                  # production server for a VPS: serves ./dist plus the APIs, does not build (docs/VPS.md)
npm test                   # node --test test/*.test.js
node --test test/sales-accuracy.test.js                      # one file
node --test --test-name-pattern "closing date" test/*.test.js # one test by name
node scripts/i18n.mjs check                                   # fail if any English text lacks Spanish
node scripts/i18n.mjs extract --out todo.json                 # list missing Spanish entries
```

On Node 18, tests that touch `crypto.randomUUID` need `node --experimental-global-webcrypto --test …`.

The dev server does not watch files: after editing, run `npm run build` (it serves straight from `dist/`) and reload. The build writes to `dist.next/` and swaps it in at the end, so a running server keeps answering during a rebuild. `test/improvements.test.js` runs `node build.mjs` into the same `dist/`.

`main` is the only long-lived branch and is what Vercel deploys. Work on a short-lived branch and open a PR; CI (Node 22) runs `npm ci`, `npm test`, `npm run build` and checks that at least 35 HTML pages were built.

## Architecture

**Page pipeline:** `site.config.mjs` (phone, DRE numbers, service area, reply hours) → `src/content*.mjs` (copy and data) → `src/templates.mjs` (every page function plus shared `head()`, `header()`, `footer()`, `leadForm()`, `imageHeader()`, `toolPage()`) → `src/pages.mjs` (`buildPages()`, the single list of `[file, html, path, lastmod]`) → `build.mjs`. The build copies `static/` into `dist/`, writes every page twice (English, and Spanish under `/es`), and fingerprints `styles.css`, `script.js`, `analytics.js` and `consent.js`. To add a page, add a template function and register it in `buildPages()`; the sitemap, the Spanish twin and `llms.txt` follow automatically.

**Spanish is generated, not authored as pages.** `src/i18n/translate.mjs` parses the rendered English HTML and replaces each visible text unit (p, h1–h6, li, label, button, option, title, alt, meta description…) using the dictionary in `src/i18n/es/*.json`, keyed by the exact English text. Inline markup is tokenised as `<a1>…</a1>`, `<em1>`, `<span1>`, and dates as `{date1}`. **Any new or reworded English copy needs a matching entry**, or `npm test` fails. Keys are exact, so case and trailing punctuation count. Put new entries in a new file under `src/i18n/es/`; stale keys are harmless. Form `value` attributes stay in English so the CRM can read them. `decoratePage()` adds hreflang tags, the language switch (inserted by regex right after `<a class="btn btn-gold header-cta" …>`, so keep that markup; `script.js` then moves the switch into the footer), and a redirect for Spanish-first browsers. Large bilingual data modules (`src/content-tools.mjs`, `src/content-handoff.mjs`) hold the English text; their Spanish lives in `src/i18n/es/seller-tools*.json`.

**Lead intake:**
- `leadForm()` is a 3-step form: address (street/city/ZIP) → situation → contact plus consent. Field names, hidden fields (`form_type`, `route_interest`, `location_interest`, `page_type`), the `#lead-form` id and the `data-*` hooks are a contract with `static/script.js` and `api/leads.js`.
- On the home page the form lives inside a full-screen `#offer-flow` overlay. Address bars (`form[data-hero-address]`) and the Seller Tools hand-off forms fill it in and open it. Other pages hand off with `/?street=&zip=&route=&situation=#get-offer`.
- `script.js` limits addresses to Kern County ZIP codes (`KERN_ZIP`).
- Optional property details are collected later on `/thank-you`.

**Serverless:**
- `api/leads.js`: public leads, idempotent, with an alert outbox.
- `api/hq.js`: the private HQ CRM, password-protected, at `/hq`.
- `api/intake.js`: an authenticated bridge from Harbison Standard.
- `api/track.js`: first-party analytics.
- `server.mjs` runs those four handlers and serves `dist/` on a VPS. It reads `vercel.json` for redirects, rewrites and headers, so add routing rules there, not in the server. `deploy/` holds the systemd unit, the Caddy config and the release script; a VPS build sets `VERCEL_INSIGHTS=off`.
- `lib/` holds the shared helpers. `static/hq/` is a separate app with its own CSS; public-site restyles don't apply to it.

## Constraints enforced by tests

- **Copy compliance** (`test/sales-accuracy.test.js`, `guide-accuracy`, `search-identity`, `no-testimonials`):
  - Never claim "no showings", "pick/choose your closing date" or "close on your timeline", in English or Spanish.
  - No testimonials.
  - Any page showing the direct-vs-listing comparison must include "Initial walkthrough; further access by agreement", "Agreed date, subject to contract, title and escrow" and the "Ask an independent broker or attorney…" disclosure.
  - The home page must say "No cleaning or repairs are needed for the initial review".
  - `/thank-you` must keep the "confirms that original request" sentence.
- **Branding** (`branding-release.test.js`): the header and footer use `call-harbison-reverse.svg`, and the footer shows both DRE numbers (agent 02059393, brokerage 02227690). The old "Harbison Buys Homes" brand must not appear anywhere.
- **`static/script.js` runs inside fake DOMs** (`bootstrap-compatibility`, `command-recovery`, `public-flow`):
  - Top-level code may only use `document.querySelector`/`querySelectorAll` and must guard other browser APIs (`matchMedia`, `IntersectionObserver`, `history`, `document.getElementById` are not available).
  - `public-flow` slices the script between marker comments such as `// ---------- Lead forms ----------`, so don't rename those.
- **Search:** page dates in `PAGE_DATES`, canonical URLs, JSON-LD validity, and `/hq` and `/thank-you` kept noindex. Keep the `answer-box` markup shape (`<div class="answer-box"><p class="answer-label">…</p><p>…</p></div>`): a test parses it and compares it with the `llms.txt` summaries.
- Many tests assert exact English strings. Before rewording copy, grep `test/` for the old wording; an `indexOf` check on a string that no longer exists can pass without testing anything.

## Design system (owner-approved; see `static/styles.css`)

- **Palette and type:**
  - Tokens live in `:root`: navy `#0B223E`, gold `#C8A260` (used on navy), gold-ink `#6E5220` (gold text on light backgrounds), paper `#FFFFFF` / `#F4F5F7` (white and a cool light grey, not cream).
  - One font family, Public Sans, for headings and text, self-hosted in `static/fonts/`. Serif headings on cream were dropped because they read as AI-made.
- **Layout:**
  - Every page opens with a navy photo header (`imageHeader()`, or `.hero-sub` / `.home-hero`). The photos are Unsplash stock URLs in `images` (`src/content.mjs`), meant to be replaced by real Kern County photos; `heroPicture()` skips the download on phones.
  - The home page is: hero with the street + ZIP bar, then a signed note from Nathanael, then the FAQ. (The four steps live on `/how-it-works`, not the home page.)
- **The owner rejects template-looking UI:**
  - no uppercase "eyebrow" labels (`.eyebrow` is hidden)
  - no italic gold accent words
  - no decorative divider lines, except a gold line under list entries
  - no card-plus-shadow grids or boxed widgets
  - no scroll-reveal animations
  - no decorative numerals (1 2 3 4, 01 02) on steps or lists; list order carries the sequence
  - no dot-and-line timelines; use plain lists with the gold line under each entry
  - no pills, icon rows or second-color headline words
  - Page-to-page transitions are a plain crossfade (View Transitions, with an `html.no-vt` fallback).
- **Copy style:**
  - Sentence case for buttons, nav and form headings ("Get my cash offer").
  - No "→" in buttons or links.
  - No "A · B · C" strings in marketing copy. The footer license line keeps its "·" because a test requires it.
  - Headings end without a period unless they are two sentences.
  - One main action per hero.
