# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Call Harbison (callharbison.com): marketing site + lead intake for Nathanael Harbison, a licensed Kern County, CA REALTOR® who buys houses directly or lists them. Static pages generated by Node, plus four small API handlers. It runs on one VPS (`server.mjs`) with its own embedded database and analytics on the server's disk; docs/VPS.md is the deployment guide and README.md the overview.

## Commands

```bash
npm ci                     # Node 22 (CI uses 22). The one dependency is PGlite, the embedded PostgreSQL.
npm run dev                # build once, then serve http://localhost:3000 with the APIs and a database in ./.data/db
npm run dev -- --mock      # same, with synthetic HQ data; HQ login password "demo"
npm run build              # writes ./dist (English + /es Spanish), sitemap, robots, llms.txt
npm start                  # production server for a VPS: serves ./dist plus the APIs, does not build (docs/VPS.md)
npm test                   # node --test test/*.test.js
node --test test/sales-accuracy.test.js                      # one file
node --test --test-name-pattern "closing date" test/*.test.js # one test by name
node scripts/i18n.mjs check                                   # fail if any English text lacks Spanish
node scripts/i18n.mjs extract --out todo.json                 # list missing Spanish entries
```

On Node 18, tests that touch `crypto.randomUUID` need `node --experimental-global-webcrypto --test …`.

The dev server does not watch files: after editing, run `npm run build` (it serves straight from `dist/`) and reload. The build writes to `dist.next/` and swaps it in at the end, so a running server keeps answering during a rebuild. `test/improvements.test.js` runs `node build.mjs` into the same `dist/`.

`main` is the only long-lived branch and is what the server deploys (`deploy/deploy.sh`). Work on a short-lived branch and open a PR; CI (Node 22) runs `npm ci`, `npm test`, `npm run build` and checks that at least 35 HTML pages were built.

## Architecture

**Page pipeline:** `site.config.mjs` (phone, DRE numbers, service area, reply hours) → `src/content*.mjs` (copy and data) → `src/templates.mjs` (every page function plus shared `head()`, `header()`, `footer()`, `leadForm()`, `imageHeader()`, `toolPage()`) → `src/pages.mjs` (`buildPages()`, the single list of `[file, html, path, lastmod]`) → `build.mjs`. The build copies `static/` into `dist/`, writes every page twice (English, and Spanish under `/es`), and fingerprints `styles.css`, `script.js`, `analytics.js` and `consent.js`. To add a page, add a template function and register it in `buildPages()`; the sitemap, the Spanish twin and `llms.txt` follow automatically.

**Spanish is generated, not authored as pages.** `src/i18n/translate.mjs` parses the rendered English HTML and replaces each visible text unit (p, h1–h6, li, label, button, option, title, alt, meta description…) using the dictionary in `src/i18n/es/*.json`, keyed by the exact English text. Inline markup is tokenised as `<a1>…</a1>`, `<em1>`, `<span1>`, and dates as `{date1}`. **Any new or reworded English copy needs a matching entry**, or `npm test` fails. Keys are exact, so case and trailing punctuation count. Put new entries in a new file under `src/i18n/es/`; stale keys are harmless. Files load in name order and a later file wins for the same key, so to change an existing translation, edit the file that holds it. Text created by scripts (`static/script.js`, `consent.js`, `analytics.js`) carries its Spanish inline in `say(english, spanish)`, not in the dictionary. Form `value` attributes stay in English so the CRM can read them. `decoratePage()` adds hreflang tags, the language switch (inserted by regex right after `<a class="btn btn-gold header-cta" …>`, so keep that markup; `script.js` then moves the switch into the footer), and a redirect for Spanish-first browsers. Large bilingual data modules (`src/content-tools.mjs`, `src/content-handoff.mjs`) hold the English text; their Spanish lives in `src/i18n/es/seller-tools*.json`.

**Lead intake:**
- `leadForm()` is a 3-step form: address (street/city/ZIP) → situation → contact plus consent. Field names, hidden fields (`form_type`, `route_interest`, `location_interest`, `page_type`), the `#lead-form` id and the `data-*` hooks are a contract with `static/script.js` and `api/leads.js`.
- On the home page the form lives inside a full-screen `#offer-flow` overlay. Address bars (`form[data-hero-address]`) and the Seller Tools hand-off forms fill it in and open it. Other pages hand off with `/?street=&zip=&route=&situation=#get-offer`.
- `script.js` limits addresses to Kern County ZIP codes (`KERN_ZIP`).
- Optional property details are collected later on `/thank-you`.

**Serverless:**
- `api/leads.js`: public leads, idempotent, with an alert outbox.
- `api/hq.js`: the private HQ CRM, password-protected, at `/hq`.
- `api/intake.js`: an authenticated bridge from Harbison Standard.
- `api/track.js`: first-party analytics, recorded on disk through `lib/analytics-store.js` (its header documents the file format and the day-compaction rule); the HQ `analytics` action reads the same store. Never store an IP, user agent, query string or title there.
- **Database:** the handlers speak Supabase's REST dialect via `fetch(${SUPABASE_URL}/rest/v1/…)`. Unless `SUPABASE_URL` is set, `lib/local-database.js` is the database: embedded PostgreSQL (PGlite) in `${STATE_DIRECTORY}/db`, opened by `server.mjs` (and `dev.mjs`) before listening; `useDatabase(env)` points `SUPABASE_URL` at an in-process shim that `lib/postgres-rest.js` turns into SQL. Its header covers the trust model, fsync, the single-process lock, backups and restore. Schema changes go in a new file in `supabase/migrations/` (applied once at start, in one transaction with its record; a failure stops the start). Tests use the same schema runner on in-memory databases (`dev/test-database.mjs`).
- **Server-first defaults:** without `VERCEL` in the environment, analytics are local, the Vercel Insights scripts are left out and GA/Metricool have no built-in IDs. `ANALYTICS_STORE`, `VERCEL_INSIGHTS` and `ANALYTICS_DEFAULTS` (`on`/`off`) override. A test that calls `api/track.js` or the HQ `analytics` action for this site must pass `ANALYTICS_STORE` or an `ANALYTICS_DIR`, or it writes into the repository's `./.data`.
- `server.mjs` runs those four handlers and serves `dist/`. It reads `vercel.json` (kept for that) for redirects, rewrites and headers, so add routing rules there, not in the server. On SIGTERM/SIGINT it flushes analytics and closes the database. `deploy/` holds the systemd unit, the Caddy config and the release script.
- `<html>` carries `data-command-phase`, `data-site-host` (the host `static/analytics.js` may run on) and `data-trackers` (the third-party tools the page can load; `static/consent.js` picks the banner wording from it). `privacyPage()` follows the same build settings, so change tracker behaviour and its wording together (`test/privacy-wording.test.js`).
- `site.config.mjs` reads the environment at import. A test of an env-dependent build renders in a child process (see `test/analytics-defaults.test.js`).
- `lib/` holds the shared helpers. `static/hq/` is a separate app with its own CSS (inline in `index.html`). It follows the same design system, and its charts are plain SVG drawn in `app.js` and `analytics.js`.

## Constraints enforced by tests

- **Copy compliance** (`test/sales-accuracy.test.js`, `guide-accuracy`, `search-identity`, `no-testimonials`):
  - Never claim "no showings", "pick/choose your closing date", "close on your timeline", "on your schedule" or "flexible closing", in English or Spanish.
  - No testimonials.
  - Any page showing the direct-vs-listing comparison must include "Initial walkthrough; further access by agreement", "Agreed date, subject to contract, title and escrow" and the "Ask an independent broker or attorney…" disclosure.
  - The home page must say "No cleaning or repairs are needed for the initial review".
  - `/thank-you` must keep the "confirms that original request" sentence.
- **Branding** (`branding-release.test.js`): the header and footer use `call-harbison-reverse.svg`, and the footer shows both DRE numbers (agent 02059393, brokerage 02227690). The old "Harbison Buys Homes" brand must not appear anywhere.
- **`static/script.js` runs inside fake DOMs** (`bootstrap-compatibility`, `command-recovery`, `public-flow`):
  - Top-level code may only use `document.querySelector`/`querySelectorAll` and must guard other browser APIs (`matchMedia`, `IntersectionObserver`, `history`, `document.getElementById` are not available).
  - `public-flow` slices the script between marker comments such as `// ---------- Lead forms ----------`, so don't rename those.
- **Search:** page dates in `PAGE_DATES`, canonical URLs, JSON-LD validity, and `/hq` and `/thank-you` kept noindex. Keep the `answer-box` markup shape (`<div class="answer-box"><p class="answer-label">…</p><p>…</p></div>`): a test parses it and compares it with the `llms.txt` summaries.
- Many tests assert exact English strings. Before rewording copy, grep `test/` for the old wording; an `indexOf` check on a string that no longer exists can pass without testing anything.
- No test covers the seller-tool logic in `static/script.js` (net sheet, quiz, checklist, deadlines). Check a change there by driving the page.

## Design system (owner-approved; see `static/styles.css`)

- **Palette and type:**
  - Tokens live in `:root`: navy `#0B223E`, gold `#C8A260` (used on navy), gold-ink `#6E5220` (gold text on light backgrounds), paper `#FFFFFF` / `#F4F5F7` (white and a cool light grey, not cream).
  - One font family, Public Sans, for headings and text, self-hosted in `static/fonts/`. Serif headings on cream were dropped because they read as AI-made.
- **Layout:**
  - Every page opens with a navy photo header (`imageHeader()`, or `.hero-sub` / `.home-hero`). The photos are Unsplash stock URLs in `images` (`src/content.mjs`), meant to be replaced by real Kern County photos; `heroPicture()` skips the download on phones.
  - The home page is: hero with the street + ZIP bar, then a signed note from Nathanael, then the FAQ. (The four steps live only on `/how-it-works`: not on the home page, and not on the situation or area pages, which link to it in one line.)
  - One left edge: reading columns (`.container.narrow`) hang from the container's left edge and are never centred. On the home page the note and the FAQ share one text column, with the portrait in the margin.
  - One gold button per screen. The header button is an outline on pages with a hero address bar, and the phone bar hides its button while the hero is on screen (`body.hero-in`).
  - No white panel on a white page. `content-visibility:auto` was removed on purpose: it made the page height jump while scrolling.
  - `/family-property-guide` is the one page without the photo header: it is a printed handout.
- **Lines, type and controls:**
  - Lists: one thin gold rule under each entry (`border-bottom:1px solid var(--gold-mid)`), nothing above the first. Table rows use `--line`, a total gets one 1px ink rule, FAQ separators stay grey.
  - Type: headings and questions are weight 600, field labels 15px/500, text 400, nothing 700. Reuse one of the existing font sizes. Page-level disclosures are 14px at no more than 65ch; hints and form notes are 13px; nothing is smaller.
  - Controls: inputs are 48px tall, radius is `var(--r)`. Use the tokens (`--field`, `--ring`, `--ring-err`, `--lift`, `--ease`, `--on-navy-2`, `--on-navy-3`) instead of new values.
  - Admin panel charts: marks are `#2A5C9A` (navy fails as a mark colour), gold marks the highlighted series, every chart has a table view, and a status is a dot with a word.
- **The owner rejects template-looking UI:**
  - no uppercase "eyebrow" labels (the markup and the CSS rule are gone; don't add them back)
  - no italic gold accent words
  - no decorative divider lines, except a gold line under list entries
  - no card-plus-shadow grids or boxed widgets
  - no scroll-reveal animations
  - no decorative numerals (1 2 3 4, 01 02) on steps or lists; list order carries the sequence
  - no dot-and-line timelines; use plain lists with the gold line under each entry
  - no pills, icon rows or second-color headline words
  - Page-to-page transitions are a plain crossfade (View Transitions, with an `html.no-vt` fallback).
- **Copy style:**
  - Sentence case for buttons, nav and form headings ("Get my cash offer").
  - No "→" in buttons or links.
  - No "A · B · C" strings in marketing copy. The footer license line keeps its "·" because a test requires it.
  - Headings end without a period unless they are two sentences.
  - One main action per hero.
  - One person's voice: "Nathanael" (and "I" in his note), never "the team" or "our licensed agent". Never state that he reviewed or wrote a page.
  - Reply time is "typically within 24 hours" everywhere; `replyHours` in `site.config.mjs` is an unconfirmed placeholder.
  - Visible headings and breadcrumbs are sentence case. `<title>` and meta descriptions keep their search form.
